# 柴怡辰作品集整體連貫性改版規格

日期：2026-08-11  
狀態：已由使用者核准 1A–9A，Hero 方向含工廠斷垣殘壁補充

## 目標

將目前各自成立、但彼此割裂的場景整理成同一趟敘事旅程。網站仍保有遊戲世界觀、Arcane 與巴洛克機械氣質，但降低灰暗、AI 微碎細節、卡片化與裝飾框堆疊。作品與可驗證成果必須成為主角。

品牌語氣：有手感的、機械性的、果斷的。  
視覺原則：共享世界，不是重複同一張背景。

## 核准範圍

完整調整 Loading、Hero、Intro、Career Tree、貓咪造咖主案例、其他作品、Interests、Build Story 與區段過場。Contact 保留功能，僅配合全站視覺系統收尾。

## 全站敘事與順序

1. Loading：以射擊建立第一個互動記憶點。
2. Hero：明亮的 Arcane × Baroque 工業城市入口。
3. Intro：角色跨越 Hero 與自我介紹，文字不再被框成履歷卡。
4. Career Tree：同世界觀的機械生命樹，說明經歷與遊戲背景。
5. 貓咪造咖：第一個、也是最重要的完整案例。
6. 其他作品：以真實內容補充廣度，不使用隨機示意圖。
7. Interests：濃縮成創意來源與玩家洞察。
8. Build Story：濃縮成製作方法與 AI 協作觀點。
9. Contact：用延續的光線與背景完成旅程。

## 背景與區段銜接

- 全站共用深藍黑／紫黑基底、星霧、金色爐火與青藍能量光。
- 每區可改變亮度、景深與局部材質，但色溫、霧層與光源方向一致。
- 不重複同一張背景圖；使用共享底色、環境光、紋理與跨區漸變建立連續性。
- 區段交界避免水平硬切。使用霧、暗角、光暈、前景剪影或角色跨區重疊作為橋接。
- 背景不得降低正文可讀性；內文控制在 65–75ch，維持合格對比。

## Loading

### 構圖

- 裁除 `gun-hand.webp` 過大的透明邊界，讓 CSS 尺寸對應可見物件。
- 桌面槍械約佔 viewport 寬 50–54%，最大約 760–800px。
- 手機使用獨立尺度，約佔 viewport 寬 82–86%，並調整出界位置以保留命中空間。
- 槍口、子彈與爆點依 viewport/槍械尺度同步放大。

### 互動

- 點擊或觸控時立刻鎖定 `clientX/clientY`，子彈準確飛向該位置。
- 等待三秒仍未互動時自動射擊到安全的預設位置，避免訪客卡在入口。
- 命中特效採混合型火光：白金亮核、橘金火星、少量青藍與紫色 Arcane 能量尾焰。
- 爆炸不是規則煙火。依序包含亮核、短促不規則火舌、高速火星、受重力影響的餘燼、局部照明與淡化離場。
- Canvas 使用 devicePixelRatio 校正，確保高密度螢幕清晰。
- 鍵盤 Enter/Space 保留預設目標；reduced-motion 以快速亮起與淡出取代子彈飛行與大量粒子。

## Hero

### 圖像方向

- 先產出兩張候選圖，不直接替換目前網站。
- 主題為較明亮的 Arcane × Baroque 工廠斷垣殘壁。
- 場景是仍能辨識原始功能的巨大機械工廠：斷裂輸送管、鏽蝕鋼梁、破碎拱頂、齒輪與鍋爐結構、遠方城市燈光或爐火。
- 移除古典柱列／柱廊；背景不得是沙漠、荒地或單純末日廢土。
- 2D 手繪輪廓結合可信的 3D 體積光、接觸陰影與材質反射。
- 提高青藍、紫羅蘭與暖金色的明度；保留深色區域，但不讓畫面整體灰黑。
- 避免過密微碎裝飾、對稱 AI 構圖、星空漩渦與無意義機械零件堆疊。

### 網站整合

- 保留現有玻璃窗、場景切換、LiquidEther 與底部選單的核心互動。
- 候選圖需預留底部文字與選單的可讀區，也要能承接右側 Intro 角色。
- 使用者看過兩張候選圖後，才決定是否替換 Hero。

## Intro

- 移除 `FramedPanel`、完整金色外框、內框與裂紋裝飾。
- 文字直接落在共享背景上，以姓名、職稱、定位文案與三項特質建立層級。
- 特質使用開放式橫列與淡水平分隔，不做卡片或側邊色條。
- 倒掛角色保留，但移至 Hero 底部右側，橫桿需依附建築／窗框，不可懸空。
- 角色向下跨進 Intro 約三分之一，成為區段橋接；桌面避開文字欄，手機只保留安全局部或隱藏。
- 縮短 Hero 結束後到姓名出現前的空白。

## Career Tree

- 重新製作日／夜兩個一致版本，保留現有日夜切換、絲帶經歷熱點與花朵遊戲熱點。
- 使用 2D 手繪輪廓搭配 3D 光影與材料感，與 Hero 的工廠世界共享金屬、青藍能量、暖金燈光與霧層。
- 樹的主要輪廓與互動熱點必須清楚，背景細節退後，不搶可點擊資訊。
- 減少 AI 微碎細節、過度對稱、星空漩渦與隨機發光物件。
- 先產出預覽，再替換正式日／夜資產；兩圖構圖與熱點位置必須一致，才能維持切換與命中區。

## 貓咪造咖主案例

### 案例位置與主張

- 放在 Career Tree 後，作為第一個完整案例。
- 主張為 IG 追蹤從 18k 成長到 30k（+67%），並用實際內容證明策略、互動與執行能力。

### 主視覺

- 使用「三萬粉－2」。
- 主指標使用：51,173 次曝光、3,898 次互動、1,476 則留言、383 次分享、50 個追蹤。
- 不用跨貼文橫向比較互動率，避免分母不一致造成誤導。
- 註解方向：把三萬粉里程碑從單向公告，轉化為讓玩家共同參與、慶祝與擴散的社群事件。

### 八張證據牆

以四個內容支柱組成不對稱素材牆，每個支柱兩張：

1. 角色與玩家需求：7 月水果貓、服裝升級攻略。
2. 玩家共鳴與互動機制：吃啥咪轉盤 Reels、世界幽浮日 Reels。
3. 活動與節慶節奏：母親節、世界海洋日。
4. 品牌與遊戲資訊：捐款收據、v1.20 版更預告。

- 社群圖像保留原始色彩與排版；統一性由網站背景、尺寸比例、標題與註解系統提供。
- Reels 使用真實封面或影片預覽，不用生成圖取代。
- 素材牆不能是八張完全相同尺寸的卡片，也不使用橫向輪播隱藏證據。

### 備選

若素材解析度或構圖不適合，依序使用：出國囉 Reels、勞動節、三萬粉－1、太空咪。

## 其他作品與後段內容

- 移除目前隨機 Picsum 圖片，不再用無關素材代表真實作品。
- 貓咪造咖完整展開；暗棋廣告測試、KOC 合作、ROG Phone 9 提案改為較精簡的真實作品模組。
- 在沒有真實圖像前，使用文字、數據與清楚的素材缺口狀態，不以假圖填充。
- Interests 濃縮為「玩家洞察／創意來源」，避免與個人簡介重複。
- Build Story 濃縮為製作方法與 AI 協作聲明，作為輔助內容，不與案例爭奪主要篇幅。
- Contact 維持現有聯絡功能，視覺上接續前段背景與光源。

## 動效與效能

- 動效只服務場景銜接、互動回饋與資訊揭露，不為每區套用相同淡入。
- 避免動畫 layout properties；優先使用 transform、opacity、mask、局部 glow。
- 所有進階動效提供 reduced-motion 替代。
- 新增影像需輸出合理尺寸的 WebP/AVIF，避免 Hero 與 Career Tree 阻塞首次載入。
- Loading 必須保證只完成一次，任何輸入方式都能離場。

## 響應式驗收

- 360×800、768×1024、910×698、1440×900 至少四組視窗檢查。
- Intro 角色不得遮住姓名、職稱或操作元素。
- Loading 爆點必須落在實際點擊位置，包含靠近邊界的點擊。
- Career Tree 熱點在日／夜圖、桌面與手機縮放後仍可命中。
- 貓咪造咖九份素材在手機上保有閱讀順序、註解與可辨識尺寸。
- 全站不得出現新的水平 overflow、不可讀文字或被動畫永久隱藏的內容。

## 素材與外部依賴

- 優先使用使用者提供的 Google Drive 資料夾取得九份貓咪造咖素材。
- 若雲端權限阻擋，只回報一次完整缺檔清單。
- Hero 與 Career Tree 候選圖由 ImageGen 製作，預覽通過後才進入正式資產替換。

## 非目標

- 不重寫聯絡表單資料流程。
- 不重新繪製真實社群素材。
- 不新增 CMS、後端、追蹤系統或資料庫。
- 不以完全相同背景圖覆蓋所有區段。
