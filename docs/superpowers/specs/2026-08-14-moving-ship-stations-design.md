# 移動飛船站點化作品集設計規格

日期：2026-08-14  
狀態：已由使用者逐段確認，進入施工

## 1. 核心敘事

網站是一艘由艦長柴怡辰駕駛、會帶訪客前往不同地點的工業飛船。訪客不是在滑一份長履歷，而是登船後依推薦航線參觀不同站點；每個站點必須是獨立網址、獨立捲動範圍，滑到底就真正結束，不能預先露出下一站。

推薦航線為：

1. 駕駛艙 `/`
2. 艦長辦公室 `/profile`
3. 航跡樹站 `/career-tree`
4. 影像分析艙 `/portfolio`

全域航線圖藏在右上角選單，招募者可以直接跳站。通訊台是全站可開啟的面板，不是一段冗長頁尾。AI 實驗艙與私人典藏艙可出現在航線圖中但標為建置中，不建立空洞長頁。

## 2. 全域航行轉場

- 船艙、工業觀景窗與操作台固定不動，只有窗外景色變暗、拉成高速光線，再換成新站景色。
- 右下角顯示原地走動的人物，採近黑剪影、藍紫輪廓光、接地陰影與向後移動的地板光帶；人物抵達後停止並淡出。
- 站名採功能型命名，只顯示目前選擇的單一語言。
- 抵達時使用 Shuffle 字元重排效果一次：不循環、不允許 hover 重播、約 0.55 秒，隨後停留約 1 秒淡出。
- `prefers-reduced-motion` 只做窗外淡出淡入並直接顯示站名，不播放字元重排或人物走路。
- 轉場期間鎖住重複操作；路由切換、焦點移動與捲動歸零只發生一次。
- Loading Page 本輪完全不修改。

## 3. 駕駛艙

- Hero 改成真正的工業飛船駕駛艙，而不是薄框背景圖。
- 觀景窗需有厚重金屬結構、鉚釘、管線、儀表、磨損與明確景深。
- 艦長人物站在操作台後，必須踩地；必要時只保留上半身，不能擋住操作區。
- 艦長辦公室、航跡樹站、影像分析艙、AI 實驗艙入口是操作台上的實體控制器或桌面擺件，不是四個普通網頁按鈕。
- 垃圾桶是駕駛艙角落的長方形金屬垃圾桶，帶粉藍螢光、瘋狂猴子感但原創的塗鴉；點擊桶蓋或塗鴉進入 `/making-of`。

## 4. 艦長辦公室

- 自我介紹保留獨立站點，不併入 Hero。
- 改成老舊工業飛船內的艦長辦公室與金屬檔案板，帶檔案照／懸賞資料板的語彙，但不能脫離工廠金屬年代感。
- 顯示艦長肖像、定位、能力、玩家視角與可靠實績；不使用大量普通深色網頁段落。
- 中文全面檢查字距、行距與換行，避免字形相黏。
- 未來私人典藏艙可放書籍、閱讀心得，以及《Rick and Morty》、《Arcane》、《Love, Death & Robots》、《我的英雄學院》、《銀魂》等喜歡的作品；本輪只保留航線資料，不製作內容頁。

## 5. 航跡樹站

- 航跡樹站是唯一能離開飛船、進入戶外的站點。
- 開場文字直接浮在樹景內；前進時文字縮小並淡出，不另占一段版面。
- 白天只顯示 Career 絲帶；夜晚只顯示 Games 花朵。
- 日夜切換控制下移，避開頂部航線選單與瀏覽器介面。
- 初始是遠景，絲帶／花朵小且不可操作；達到靠近門檻後才放大、亮起並可點。
- 桌面滾輪向前（一般向上滾）、觸控板雙指向上才前進放大；反方向拉遠。手機向上推動前進。
- 鏡頭互動期間固定在場景，不會滑出站點。
- Career 絲帶統一為低飽和、帶細微金光的黃色，必須貼合枝枒。
- Games 花朵統一成同一設計家族，每朵都必須接在枝枒，不能漂浮；不同遊戲可用色彩與細節差異辨識。

## 6. 影像分析艙

- 保留 Circular Gallery，並置於厚重、明顯的工業圓形觀景窗／掃描儀中。
- Gallery 每張卡片代表完整案例：第一批為「貓咪造咖」與「暗棋廣告測試」；KOC 等資料完整後再加。
- 點選案例後不換普通內頁：圓窗留在背景並降低亮度，金屬分析桌由下方升起。
- 左側使用 Stack 瀏覽多張圖片、輪播頁與影片；支援拖曳、上一張、下一張、頁數及鍵盤操作。
- 影片預設只顯示封面與播放鍵；使用者主動播放，換卡、關閉或離站時暫停，返回時保留進度但不自動播放。
- Stack 每切換一張素材，右側同步切換：素材目的、我的工作、成效證據、學習。成效列點格式統一。
- 關閉分析桌後回到 Gallery 原本選中的案例與位置。
- 手機改上下排列；圖片、控制與說明皆需 44px 以上可操作區。

## 7. 場景內離站控制與通訊台

- 刪除獨立的 Chapter Exit 區塊。
- 每站底部把「返回駕駛艙／前往下一站」整合成場景中的控制台，不能像另一張網頁卡片。
- 右上角全域航線圖包含站點、建置中標記與通訊台入口；開啟時需 focus trap、Escape、背景鎖定與焦點返回。
- 通訊台移除抽象結尾句，只保留有效 Email、LinkedIn、履歷與留言。

## 8. 網站製作檔案與協作者肖像

- `/making-of` 仍是垃圾桶內的製作檔案，不代表其中人物是垃圾。
- 未來阿居（Codex）與克克（Claude）的自畫像放在垃圾桶內側桶蓋，做成協作者貼紙／工作證，旁邊標示協助內容。
- 本輪不生成肖像；先等待阿居與克克各自提供形象描述。
- 在描述尚未提供前，只保留兩個「協作者席位」資料位置，不使用假人物或佔位照片。

## 9. 資訊架構與路由

- `/` 駕駛艙
- `/profile` 艦長辦公室
- `/career-tree` 航跡樹站
- `/portfolio` 影像分析艙
- `/making-of` 網站製作檔案
- AI 實驗艙、私人典藏艙在航線圖標示建置中，不建立空頁。
- 任一正式站點網址重新整理後都應直接顯示該站；Loading 只在首次進站顯示一次。

## 10. 驗收標準

- 站點彼此不會因捲動而相互露出。
- 360×800、390×844、644×698、795×698、1280×720、1440×900 無水平溢出。
- 鍵盤、Escape、焦點返回、body lock、44px targets、單一語言與 reduced motion 全部可用。
- 航跡樹的前進方向必須是滾輪向前／向上，且遠景不可誤觸素材。
- 作品 Stack 的視覺卡、右側說明、頁數與影片狀態保持同步。
- Loading 無任何行為或視覺回退。
